# Финальный отчёт — голосовая диктовка работает (для GLM)

Дата: 2026-08-19, вечер. Система в продакшене, тема «источник сигнала» ЗАКРЫТА.

## Развязка: переворот был правильным — источник перепутан

Серия фактов, которая привела к решению:

1. Стук по петличке → индикатор Windows молчит; стук по корпусу ноутбука → реагирует. **Всё время Windows слушал встроенный микрофон ноутбука**, а не BOYA. Все прошлые «рабочие» записи (пик 18-21%) — заслуга встроенного, голос через комнату.
2. Пользователь выбрал в настройках вход, реагирующий на петличку (гнездо ноутбука) — настройки «Громкость 100%» + отключены все звуковые эффекты (в новых драйверах вкладки «Улучшения»/буста нет — цифровой гейн фиксирован).
3. **Петличка (BOYA BY-M1 Pro II) в Smartphone-режиме честно даёт 3-5% пика** — whisper не слышит. В **Camera-режиме — 0% (полный ноль)**: на этом ноутбуке режим несовместим с гнездом (электрическая распайка), гипотеза «Camera горячее» умерла эмпирикой.
4. **Но выяснилось, что и это измерение было не тем устройством**: пользователь диктовал, пока в настройках была выбрана камера. Камера дала 31% пика, но распознавание — мусор `", , . ."` (вебкамера слышит неразборчиво).
5. **Финальный выбор пользователя: «Микрофон (Senary Audio)» №1 (гнездо) — с ним диктовка РАБОТАЕТ**: 43.5-сек запись, пик 18%, распознана слово в слово через whisper. Устройство переименовано в «BOYA (Senary Audio)» (Windows 11 позволяет переименовывать), второй вход остался «Микрофон (Senary Audio)» (встроенный).
6. **Стук-тест (после переименования): ПОЛОЖИТЕЛЬНЫЙ** — щелчки по капсюлю петлички при выбранном «BOYA (Senary Audio)» дёргают индикатор Windows. Подтверждено: **в тракте физически петличка BOYA** (гнездо ноутбука), а не встроенный массив. Показания 3-5% ранее — артефакт другого выбранного устройства в тот момент (путаница с камерой/вторым Senary). Рабочая конфигурация: BOYA → гнездо → «BOYA (Senary Audio)» → RDPSource → whisper. Все цифры таблицы валидны.

## Что это значит для твоих прошлых советов

- «Встроенный микрофон — уже работающая система» — подтвердилось на 100%: он и был рабочей системой весь день.
- «План Б (ffmpeg dshow на Windows) уровень НЕ решит» — согласны; теперь и не нужен: гнездо с петличкой работает (18% пика, RMS 500-1000, whisper доволен).
- Гипотеза «севшая батарейка/дефект BOYA» — **не проверена**: петличка в Camera даёт 0, в Smartphone 3-5% через гнездо. Телефон-тест не делали. Может быть, телефон покажет нормальный уровень — тогда вопрос к гнезду/распайке, но нам это уже не мешает: **выбранное устройство = гнездо = работает** (подозреваем, что «рабочее» устройство на самом деле встроенный массив ноутбука, а BOYA осталась на 3-5% — пользователь не смог отличить одинаковые имена; переименование теперь позволит сделать это за 1 минуту, если захотим).

## Что починено в пайплайне за сессию

1. **Гонка чтения результата (главный баг дня).** Раньше: AHK запускал `cmd /c wsl.exe stop > OUT`, ждал `FileGetSize(OUT) > 0` и читал — ловил частично записанный файл (пустые строки), вставлял пустоту. Теперь: record.sh пишет `/tmp/dictate_out.txt` + `touch /tmp/dictate_out.done` (маркер готовности), AHK ждёт маркер `\\wsl.localhost\Ubuntu\tmp\dictate_out.done` (UNC доступ к WSL из Windows подтверждён) и читает текст. Гонок нет.
2. **Инструментация** (по твоему плану): `ERR:curl(rc)`, `ERR:http(code)`, `ERR:json`, `ERR:busy` (flock), `ERR:gated_wav` (валидация `getnframes()>1600`), `SILENCE` — четыре различимых исхода.
3. **Самолечение**: AHK при `ERR:curl/http/busy` → `wsl.exe -d Ubuntu -u root -e systemctl restart whisper-server` (WSL root без пароля — подтверждено, работает).
4. **Универсальный фильтр галлюцинаций**: все сны whisper на тишине/тоне идут в `*звёздочках*` (музыкальная нотация) — `grep '*'` → SILENCE. Поймал «*Звук звука*», «*Разговор*», «*говорит по-говорому*», «*звук по-профессии*» и классику «Редактор субтитров Н.Закомолдина». Чёрный список оставлен как второй слой.
5. **`-t 8` vs `-t 16`**: 16 МЕДЛЕННЕЕ (3.47с vs 2.92с на 14.2с клипе) — SMT не помогает ggml, оставлено 8.
6. **Таймаут AHK**: 15с → 60с (длинные диктовки: 43.5с запись = ~11с обработки).
7. **RMS-пречек**: порог 60 (цифровая тишина ~0-30). Известный риск: шумная сессия может поднять пол; если начнёт есть тихую речь — опустить до 30 (твоя рекомендация принята, следим).
